# Scheduled optimisation controls

These controls examine training and representation stability. They do not replace
the shorter primary fitted outputs or establish a ranking of fully optimised
models. The complete declared grid has three empirical datasets, three
computational seeds and four configurations, giving 36 fits.

## Inputs and environments

Follow `analysis/README.md` to create the modern analysis environment, the separate
Python 3.7 and TensorFlow 1.15 environment, and the pinned SAUCIE source checkout.
Do not run the legacy model code in the modern environment. The same environment
specifications apply to these controls and the preceding configuration controls.

The verified control-input archive is installed with

```bash
python -m analysis.download_control_inputs
```

Its default training arrays are in `analysis/data/deep_control_inputs/controls`.
The arrays have Unicode cell and gene identifiers and require no pickle loading.
Their numeric inputs are identical to those of the preceding controls. Analysis
objects used for endpoint scoring must retain the same ordered cells, annotation
fields and PCA reference. They can be downloaded with `analysis.download_inputs`
or generated by the documented public-source preprocessing workflow. These are
distinct input routes, not interchangeable claims of fresh refitting.

## Fitting

Run from the repository root in the modern analysis environment. The launcher
starts model jobs in the explicitly selected legacy interpreter. The following
PowerShell example uses the environment variables configured in the main guide

```powershell
python -B -m analysis.optimization_controls.optimization_followup --input-dir analysis/data/deep_control_inputs/controls --output-dir analysis/runs/scheduled_controls --saucie-source $env:SCDR_SAUCIE_SOURCE --legacy-python $env:SCDR_LEGACY_PYTHON --workers 3 --threads 4
```

For Bash, substitute `$SCDR_SAUCIE_SOURCE` and `$SCDR_LEGACY_PYTHON`. Use a fresh
output directory. `--prepare-only` records all jobs and input/source hashes without
fitting. `--resume` accepts only the same registry and completed compatible jobs;
an incomplete attempt is retained for inspection rather than overwritten.

scScope completes 2,500 epochs at learning rates 0.0001 through epoch 1,000,
0.00001 through epoch 1,750 and 0.000001 thereafter. Each SAUCIE configuration
completes 30,000 updates at rates 0.001 through update 10,000, 0.0001 through
update 20,000 and 0.00001 thereafter. There is no endpoint-selected early stopping.
Labels are not passed to the fitting objective or schedule.

The four configurations are recurrent scScope, reconstruction-only SAUCIE,
reconstruction under the SAUCIE task-branch architecture, and the explicitly
labelled task-enabled numerical sensitivity. The last preserves the previously
disclosed nonnegative finite squared-distance correction and is not unmodified
task-enabled SAUCIE. No failed fit is replaced by coordinates from another method.

## Saved-state checks and endpoints

After all fits finish, run the read-only saved-state audit in the legacy runtime
and score the matched outputs in the modern runtime

```powershell
python -B -m analysis.optimization_controls.audit_gradients --controls-dir analysis/runs/scheduled_controls --legacy-python $env:SCDR_LEGACY_PYTHON
python -B -m analysis.optimization_controls.score_controls --controls-dir analysis/runs/scheduled_controls --analysis-objects analysis/data/analysis_objects
```

There are 45 actual state evaluations, comprising baseline and terminal states
for nine scScope fits and terminal states for 27 SAUCIE fits. The original SAUCIE
saver retains only its final parameter state. Earlier saved coordinate arrays are
available, but baseline parameter states and their diagnostic-mean gradients are
not reconstructed or invented. The audit executes no training update and verifies
that checkpoint bytes remain unchanged.

scScope's full-data monitor sums the two recurrent masked Frobenius residual
norms relative to the observed input norm. The installed training objective uses
unsquared masked minibatch Frobenius norms. This differs from the per-cell squared
formulation in the original paper. The original last-recurrence monitor is also
retained. SAUCIE monitoring averages losses over four fixed diagnostic batches,
not one joint task-loss batch. The gradient of their mean is computed by averaging
parameter gradients before taking the norm.

Scoring uses the published 15-neighbour, fixed-subset trustworthiness, fixed-pair
distance-rank and eight-resolution Leiden definitions. It produces 90 endpoint
records, including baseline and terminal outputs of all fits and two additional
projections of each terminal scScope representation. Labels are used only after
fitting. Seeds, cells, pairs and checkpoints are not biological replicates.

## Plotting

```bash
python -B -m analysis.optimization_controls.plot_controls --controls-dir analysis/runs/scheduled_controls --output-dir outputs/scheduled_controls
```

The plotter requires complete measured inputs and their matching source hashes;
it refuses partial results. PDF, SVG and PNG files are placed in the selected
output's `figures` directory. Existing main figures and combined supplements are
not overwritten. The supplied scalar plot data can be used separately from
refitting. Raw losses, gradients and coordinate changes are continuous training
diagnostics. A small learning rate, passed loss-stability rule or finite gradient
does not prove a stationary point, a global optimum or biological reliability.

## Primary scScope seed policy

The historical primary call set NumPy and an outer TensorFlow seed, but scScope
creates a new graph internally and samples training minibatches through Python's
random module. Those two sources were not fully seeded by the old call. The
archived fitted arrays, rather than an assertion of deterministic original
training, define exact replay of the published coordinate realisations.

The public `analysis/legacy_deep_runner.py` additionally seeds Python sampling
and the actual graph created by scScope. Two separate-process, single-thread
PBMC3k fits at the primary 300-epoch budget and seed 17 produced identical native
and reconstruction arrays. The recorded publication-budget workflow used the
preceding primary call; this targeted correction check is not relabelled as a
complete rerun of all its fits. The scheduled optimisation controls already set
Python, NumPy and graph-local TensorFlow seeds explicitly. The distinction and
actual repeated-array hashes are retained in the execution metadata.
